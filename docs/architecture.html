Architecture Cheat Sheet · Draft 2

Thor

Every function, file, API, and artifact in the reliability pipeline — traced end to end, so the chain is legible even to the people who built it.

Thor reads top to bottom because the system runs top to bottom: sensor data enters at the bottom of the stack and a governed decision surfaces at the top, on a screen an engineer is actually looking at. Historical or live telemetry is replayed through MQTT into a single Control Plane, which hands each request to one LangGraph orchestrator holding five deterministic toolboxes — Data, ML Architect, Validation, Reliability, and MLOps. There is exactly one agent in this system, in the AI-reasoning sense: the Orchestrator. Everything it calls is plain code with no model inside it.

Data gets profiled and regime-checked before anything trains on it; the ML Architect picks a task and searches three tree-based model families; Validation attacks the result for leakage, calibration, and warning lead time before anointing a champion; Reliability assembles evidence — SHAP values plus cited manual passages — that the Orchestrator turns into an explanation and a cost comparison; MLOps watches the whole thing for drift long after the demo ends. Every toolbox can propose an action, but none can execute one. That's the Human Approval Gate: the one place a plan becomes a person's decision. Thor doesn't replace the MES a plant already runs — the Decision Contract that comes out of the gate is the handoff artifact, built to feed one, not become one.

Thor and Bolt, at a glance

// the whole system versus the conversational component inside it

Thor · the system

An agentic AutoML + MLOps platform for predictive maintenance

Seven Docker Compose services and one governed pipeline. Telemetry arrives over MQTT (Mosquitto) into a FastAPI control plane and a TimescaleDB hypertable; a LangGraph orchestrator — the only component that calls Claude, and only to route and to phrase — drives five deterministic toolboxes: regime-aware profiling, an Optuna search over Random Forest / XGBoost / LightGBM ranked by the Industrial Model Score and tracked in MLflow, asset-level validation with calibration and lead time, SHAP explanation with a cost comparison, and an MLOps lifecycle that promotes the champion to ONNX Runtime at the edge.

Its product is the Decision Contract: an immutable, hash-linked record of prediction, evidence, and recommended maintenance window that stops at the Human Approval Gate and, once an engineer approves, hands off to the plant's existing MES/CMMS.

Owns: every number, every model, every action. Never: lets the LLM compute a metric, a cost, or a citation.

Bolt · a component of Thor

The conversational surface over the RAG pipeline

Bolt is the copilot persona in the Copilot screen. It sits on top of the Reliability toolbox's retrieval layer — a Chroma index built locally from the plant's maintenance manuals (MiniLM embeddings via ONNX Runtime, no external embedding API) whose cited passages already ground every Decision Contract — and exposes that evidence in chat: why this motor is at risk, which SHAP drivers say so, which manual section matches, what is waiting for approval.

It reaches the data only through a fixed set of read-only tools on the same FastAPI control plane (get_fleet, get_asset, get_contract, get_run, list_pending_approvals), and its prompt confines it to numbers those tools returned. Without an API key it still answers, from templates over the same tools.

Owns: the explanation in conversation. Never: approves, promotes, trains, or invents a citation — the retrieval decides what may be quoted.

One request, start to finish

// a concrete trace — MTR-042's bearing starts degrading, replayed telemetry to an approved work order

  1. streaming/replay/replay.py publishes a row for MTR-042 to MQTT topic telemetry/MTR-042 — vibration RMS ticking up, timestamp 2026-09-24T14:31:58Z.
  2. 02 FastAPI's MQTT subscriber (apps/api/routes/telemetry.py) writes the row into the telemetry hypertable in TimescaleDB.
  3. The Fleet screen (01) polls GET /fleet; MTR-042's health score drops 94 → 81. The engineer opens Asset 360, which calls POST /pipeline/run for that asset.
  4. 03 Orchestrator starts a typed GraphState (run_id=r_9f21) and makes its first Claude call: "given this state, call 04.profile_dataset."
  5. 04 reads the last several hours of telemetry for MTR-042, returns a Data Quality Contract — quality 96.4/100, regime R3 (high load).
  6. 05 infers the task (classification), engineers vibration + process features, and runs Optuna over Random Forest / XGBoost / LightGBM — three runs logged to MLflow under experiment mtr-042-bearing.
  7. 06 backtests all three on held-out machines, computes calibration and warning lead time, and picks XGBoost (mlflow run 8a1c…) as champion, model_version=v17.
  8. 07 assembles evidence: explain() returns the top SHAP features; retrieve_manual_context() does a Chroma similarity search and returns the two closest passages from data/manuals/motor-maintenance.md §4.2; calculate_failure_cost() compares maintain-tonight ($8,400) vs. Friday ($5,900) vs. run-to-failure ($46,700).
  9. 03's second and only other Claude call turns that evidence bundle into the actual explanation sentence. create_decision_contract() inserts one immutable row, dc_MTR-042_20260924143210, status pending.
  10. 09 — the ModelOps/Asset 360 screen renders the contract with its full evidence trail; the engineer clicks Approve. POST /approvals/{id}/decision inserts a new row in the approvals table, foreign-keyed to the contract. The contract itself is never edited — approval is a linked row, not a mutation.
  11. Approval fans out: 08's deploy_edge() exports v17 to models/mtr042_v17.onnx, mounted into 10's edge container; the contract's recommended action becomes the logged work-order text handed off toward the plant's MES/CMMS.

Function reference

// same order the request actually travels · FILES / EXPOSES / READS / WRITES / DEPENDS ON for each

01

Frontend & Copilot — client surfaces

What a judge actually watches. Five React screens plus one chat surface, all hitting the same API — nothing below this line is visible unless it shows up here.

  • FleetAggregate health across every asset, sorted by risk.
  • Asset 360Single-asset deep dive: live trace, health score, current fault.
  • AutoML StudioShows DATA → TASK → FEATURES → MODELS → VALIDATE → DEPLOY with evidence at each stage.
  • ModelOpsChampion vs. challenger comparison; approve / deploy buttons.
  • Copilot · BoltChat over the RAG-grounded evidence, through read-only tools on the same API.
FILES — apps/web/src/screens/{Fleet,Asset360,Studio,ModelOps,Copilot}.tsx
READS — GET /fleet, GET /assets/{id}, GET /pipeline/{run_id}, GET /models from 02
WRITES — POST /approvals/{id}/decision, POST /copilot/chat to 02
DEPENDS ON — VITE_API_BASE_URL
02

FastAPI Control Plane

The one door everything walks through — serves the frontend, streams live updates, exposes the approve/reject endpoint, and is what Bolt's tool calls hit too.

  • ingest_telemetry()Writes incoming MQTT rows into TimescaleDB.
  • get_fleet_state()Direct reads for dashboard views that don't need agent reasoning.
  • invoke_pipeline()Hands a request to the LangGraph Orchestrator.
  • record_approval()Writes a human's approve/reject decision.
FILES — apps/api/main.py, apps/api/routes/{telemetry,fleet,pipeline,approvals,models,copilot}.py
EXPOSES — POST /ingest · GET /fleet · GET /assets/{id} · POST /pipeline/run · GET /pipeline/{run_id} · WS /ws/runs/{run_id} · GET /models · POST /approvals/{id}/decision · POST /copilot/chat
READS — telemetry stream from 10 (MQTT)
WRITES — raw rows → 10 telemetry hypertable; invokes → 03
DEPENDS ON — DATABASE_URL, MQTT_BROKER_URL — not the Claude key; that's one layer down
03

LangGraph Orchestrator — the actual "agent"

One stateful graph, five toolboxes, holding state across the whole pipeline. It's the only file in the entire codebase that calls an LLM — everything it calls is deterministic code.

  • route()Decides which toolbox function runs next based on pipeline state.
  • await_approval()Pauses the graph at the Human Approval Gate node.
  • resume()Continues once a human decision is recorded.
FILES — apps/api/orchestrator.py, apps/api/graph_state.py
EXPOSES — nothing public; called only via invoke_pipeline() from 02
READS — typed GraphState; tool schemas exported by 04–08
WRITES — updated GraphState; two Claude calls per run (routing, then final explanation)
DEPENDS ON — ANTHROPIC_API_KEY — the only place this key is read, anywhere
04

Data Reliability Agent

Turns raw telemetry into a scored "can we trust this" report before anything trains on it.

  • profile_dataset()Schema, sampling rate, asset/row counts, a data-quality score.
  • detect_missingness()Missing windows, sensor flatlines.
  • detect_regime()Clusters operating states (RPM/load/startup) so a load change isn't mistaken for a fault.
  • validate_schema()Units, timestamps, duplicates.
FILES — agents/data_agent/profiling.py
READS — telemetry rows for the asset/window from 10
WRITES — data_quality_contract row → 05
DEPENDS ON — nothing external; pandas/numpy only
05

ML Architect Agent — the AutoML brain

Decides what kind of model this data supports, engineers signal-appropriate features, and runs the search.

  • infer_task()Classification vs. remaining-useful-life regression.
  • build_feature_pipeline()RMS, kurtosis, crest factor, temperature slopes and deltas for vibration; rolling stats for process telemetry — regime-normalized.
  • launch_trial()Optuna search over Random Forest / XGBoost / LightGBM.
  • compare_models()Ranks candidates by the Industrial Model Score (recall + lead-time + precision + calibration + latency), not raw accuracy.
FILES — agents/ml_architect/{automl,features}.py
READS — Data Quality Contract (04) + raw telemetry (10)
WRITES — model artifacts + metrics → MLflow run (10); candidate list → 06
DEPENDS ON — nothing external; local compute only
06

Validation Agent — the trust gate

Attacks its own model before it's allowed to matter. The checkpoint that separates a working system from a hackathon toy.

  • detect_leakage()Temporal, feature, and train/test asset leakage.
  • run_backtest()Time-ordered, asset-level split — validated on machines the model has never seen.
  • calibrate_probabilities()Is "80% confident" actually right 80% of the time.
  • compute_lead_time()Median and P90 warning time before the actual failure.
  • estimate_rul_interval()Quantile regression for a P10–P90 range, not a single number.
FILES — agents/validation/checks.py
READS — candidate models + MLflow run IDs from 05
WRITES — validation_report row + champion pointer → 07, 08
DEPENDS ON — nothing external
07

Reliability Agent — predictive → prescriptive

Assembles the evidence that turns a validated prediction into "here's what to do about it, and why" — the sentence itself is drafted by the Orchestrator (03) from this evidence, not by this toolbox. This is also the RAG pipeline that Bolt talks over.

  • explain()SHAP feature importances, as structured data — not prose.
  • retrieve_manual_context()Chroma similarity search over ingested manuals — top matching passages, not a hallucinated citation.
  • calculate_failure_cost()Expected cost = P(failure) × consequence + planned-maintenance cost.
  • find_maintenance_window()Compares maintain-now / maintain-later / run-to-failure.
  • run_whatif()Reliability sandbox — re-scores inference under a hypothetical operating condition.
  • create_decision_contract()Immutable insert: model version, evidence, confidence, recommendation.
FILES — agents/reliability/{explain,rag,cost,contract}.py, corpus at data/manuals/*
READS — champion model (06), live inference (10), vector index (10)
WRITES — evidence bundle → 03 (drafts prose) → decision_contract row → 09
DEPENDS ON — local sentence-transformers model; no external embedding API, no direct Claude call here
08

MLOps Agent — keeps the system honest over time

Nothing gets promoted without a real comparison and a human's click. Model lifecycle management, not just training.

  • register_model()MLflow registry entry: params, metrics, git SHA, dataset version.
  • compare_champion()Challenger vs. current production model, side by side.
  • promote()State transition (candidate → validated → shadow → production) — tracked as a database state, not live traffic-splitting.
  • detect_drift()Population-stability-index check on incoming feature distributions vs. training.
  • deploy_edge()Exports the champion to ONNX, pushes it to the edge container.
FILES — agents/mlops/{lifecycle,drift}.py
READS — Validation Report (06); rolling telemetry window (10) for drift
WRITES — MLflow registry stage → 10; promotion request → 09; on drift, re-invokes 05
DEPENDS ON — MLFLOW_TRACKING_URI
09

Human Approval Gate

The actual governance boundary. Every consequential action stops here until an engineer clicks approve — "LLM plans, deterministic code computes, engineer decides," made literal in the architecture instead of just stated in the pitch.

  • present_evidence()Shows the recommendation with its full evidence trail before asking for a decision.
  • record_decision()Inserts a new approvals row referencing the contract — the contract itself is never edited.
FILES — apps/api/routes/approvals.py; rendered by 01's Asset 360 / ModelOps screens
EXPOSES — POST /approvals/{id}/decision
READS — decision_contract / promotion_request rows awaiting a decision
WRITES — new approvals row (decision, approver, timestamp)
DEPENDS ON — nothing beyond the database
10

Data, Streaming & Edge Layer

The plumbing everything above sits on — deliberately unglamorous. Nothing here shows up in a demo video, so nothing here is over-built.

  • Mosquitto + replayPublishes a historical sequence at accelerated time — looks live, stays 100% reproducible.
  • TimescaleDBTelemetry hypertable, asset registry, decision contracts, approvals.
  • MLflowExperiment tracking + model registry, artifacts on a mounted Docker volume.
  • Chroma indexVector store for the manual corpus, persisted to its own Docker volume.
  • Edge InferenceONNX Runtime + a small FastAPI service, subscribed directly to MQTT.
FILES — streaming/{mqtt,replay}/, data/{simulator,benchmark,manuals}/, edge/main.py, infra/docker-compose.yml
EXPOSES — MQTT topics telemetry/{asset_id}, predictions/{asset_id}
READS — data/simulator/ output for replay; AI4I 2020 CSV for the benchmark script
WRITES — telemetry rows; the mounted .onnx file after an approved promotion
DEPENDS ON — MQTT_BROKER_URL
